# مكتبة الأوامر

أوامر جاهزة للصق في Claude Code. ما بين `< >` تستبدله أنت.

## البدء والتنفيذ

**جلسة التحضير الأولى على الخادم** (تثبيت الأدوات، ربط GitHub، فحص Cloudflare Tunnel، تقرير الفهم). تُشغَّل مرة واحدة من مجلد المشروع على الخادم:

```text
هذه جلسة التحضير الأولى لمشروع أكاديمية سُرى. أفوّضك فيها بتجهيز بيئة الخادم وربط المستودع بـ GitHub. هذه ليست حزمة عمل: لا تكتب أي كود للمشروع، ولا تبدأ WP-0.1.

السياق:
- أنت تعمل على الخادم الذي سيُبنى عليه المشروع. الخادم متصل بالإنترنت عبر Cloudflare Tunnel، وعليه مشاريع أخرى يجب ألا تتأثر.
- المستودع البعيد: https://github.com/abd0175149-droid/Sura-academy
- قد تكون مصادقة GitHub موجودة على الخادم من مشاريع سابقة.

قواعد هذه الجلسة:
1. قبل أي تثبيت أو تغيير على مستوى النظام، اعرض الخطة وانتظر موافقتي.
2. لا تغيّر الإصدار الافتراضي لأي أداة تستخدمها مشاريع أخرى. ولا تلمس حاوياتها أو خدماتها أو مواقعها أو إعداد Cloudflare Tunnel.
3. لا تقرأ أي رمز أو كلمة مرور ولا تطبعه ولا تنسخه، ولا تبحث عن رموز في ذاكرة المشاريع الأخرى أو ملفاتها. استخدم مصادقة gh وgit الموجودة على الخادم فقط. إن لم تكن موجودة فتوقف واطلب مني تسجيل الدخول بنفسي.
4. الـ hooks مكتوبة بـ PHP، فظهور أخطائها قبل تثبيت PHP متوقع، ولذلك يُثبَّت PHP أولاً.

المرحلة 1 — الفهم (قراءة فقط):
اقرأ بالترتيب، ولا شيء غيره من docs/:
- START_HERE.md

- docs/00-governance/decisions.md: جدول الملخص، وتفاصيل البنود Open فقط

- .claude/settings.json
CLAUDE.md محمّل لديك تلقائياً، وهو المرجع الحاكم. لا تقرأ docs/01-product/spec مباشرة.

المرحلة 2 — فحص الخادم (أوامر قراءة فقط):
- أين تعمل: المستخدم، المجلد، نظام التشغيل وإصداره، المعالج والذاكرة والقرص.
- الأدوات المثبتة وإصداراتها:
  - git وgh
  - php: كل الإصدارات، والافتراضي منها
  - composer
  - node وnpm وnvm
  - docker وdocker compose
  - flutter وdart
  - chrome أو chromium
  - cloudflared
- ما يعمل حالياً، حتى لا نتعارض معه: المنافذ المستمعة، الحاويات، خدمات nginx وphp-fpm وpostgres وredis وcloudflared.
- Cloudflare Tunnel: هل الإعداد محلي (config.yml) أم مُدار من لوحة Cloudflare؟ إن وُجد config.yml فاقرأ قواعد ingress فقط، ولا تفتح ملفات الاعتماد.

ثم اعرض خطة التثبيت في جدول أعمدته: الأداة، المطلوب، الموجود، الإجراء، هل يحتاج sudo، الأثر على المشاريع الأخرى.

المطلوب تثبيته:
- PHP 8.4 بجانب أي إصدار قائم، مع الامتدادات: pgsql، redis، intl، mbstring، xml، curl، zip، bcmath، gd، pcov.
- Composer 2.
- Node.js LTS عبر nvm للمستخدم.
- intelephense.
- Docker مع compose.
- Flutter stable مع تفعيل الويب.
- Chromium أو Chrome للاختبارات دون واجهة، ومتصفحات Playwright.
- gh.

لا Android SDK ولا Xcode على الخادم.

توقف هنا وانتظر موافقتي.

المرحلة 3 — التثبيت (بعد موافقتي):
- نفّذ الخطة بالترتيب، وPHP أولاً. تحقق من إصدار كل أداة بعد تثبيتها.
- إن احتاج sudo كلمة مرور لا تملكها، فأعطني الأوامر لأنفذها بنفسي.
- ثبّت إضافات Claude Code:
  claude plugin marketplace add flutter/agent-plugins
  claude plugin install dart-flutter@dart-flutter
  claude plugin install php-lsp@claude-plugins-official
  إن لم يُعثر على السوق الرسمي، فأضفه أولاً بـ: claude plugin marketplace add anthropics/claude-plugins-official
  ثم أخبرني إن لزم إعادة تشغيل الجلسة.
- تحقق من وجود CONTEXT7_API_KEY في البيئة دون طباعة قيمته.

المرحلة 4 — المستودع وGitHub:
- تحقق من المصادقة بأمري gh auth status وgit ls-remote على المستودع.
- إن كان المستودع البعيد فارغاً:
  - هيّئ git والفرع main.
  - أنشئ أول commit للحزمة كما هي برسالة «chore: project constitution and execution plan».
  - اطلب إذني قبل الدفع.
- إن لم يكن فارغاً: توقف وأخبرني بمحتواه قبل أي دمج. لا دفع قسري أبداً.
- اقترح حماية الفرع main (PR إلزامي، وفحوص CI ناجحة)، ولا تطبّقها قبل موافقتي.

المرحلة 5 — التوثيق:
- أنشئ docs/04-guides/server-environment.md يتضمن:
  - ما وجدته على الخادم، وما ثبّته بإصداراته ومساراته.
  - المنافذ المحجوزة لهذا المشروع، وطريقة عمل النفق.
  - خطة أسماء المضيفين:
    - الـ API وتطبيق الأسرة وبوابة المعلمة والموقع، كلها تحت نطاق رئيسي واحد، لأن ملفات ارتباط Sanctum تتطلب ذلك.
    - جميعها خلف Cloudflare Access، ويُستثنى المسار /webhooks/* وحده لمزودي الدفع والفيديو.
  - خدمات البيانات (PostgreSQL وRedis وMinIO وMailpit وClamAV وGotenberg) مربوطة على 127.0.0.1 فقط، بمنافذ لا تتعارض مع المشاريع الأخرى.
  - لا تعدّل إعداد النفق؛ اكتب القواعد المطلوبة لأضيفها بنفسي.
- أضف في decisions.md بنداً مفتوحاً D-32 نصه: «دور هذا الخادم: تطوير ومعاينة فقط، أم تجربة ميدانية أو إنتاج؟».
  - اذكر أثره على موطن البيانات (المواصفات تشترط استضافة أوروبية)، وعلى النسخ الاحتياطي والأمن.
  - اسألني عن مزود الاستضافة وموقعه.
  - حتى يُحسم: لا بيانات حقيقية على هذا الخادم.
- أنشئ commit لهذه الملفات، وادفعها بإذني.

المرحلة 6 — التقرير، بالعربية وفي 70 سطراً على الأكثر:
أ. فهمك للمشروع في 5 إلى 7 أسطر.
ب. طريقة عملك: ترتيب المراجع، العمل عبر /sura-wp فقط، موافقتي على التصميم، الاختبار أولاً، /verify، المراجعون، ومتى تتوقف وتسألني.
ج. جدول البيئة النهائي، مع حالة الـ hooks والمهارات والوكلاء وخوادم MCP. خادم laravel-boost لن يعمل قبل WP-0.1، وهذا متوقع.
د. GitHub: حالة المصادقة، وحالة المستودع، والدفع.
هـ. Cloudflare Tunnel: ما وجدته، والقواعد المطلوب مني إضافتها.
و. أين نحن: المرحلة، والبوابة القادمة وتاريخها، وأول خمس حزم وما تحتاجه مني لكل منها.
ز. القرارات المفتوحة، ومنها D-32، وما يجب أن أحسمه أولاً.
ح. نتيجة spec-reader لـ ATT-03 في 8 أسطر، مع الملف والسطر.
ط. أي تعارض أو غموض لاحظته، مع الملف والسطر، أو «لا شيء».
ي. الخطوة التالية بالضبط.
```

## عند الانحراف أو الشك

**Claude بنى شيئاً خارج النطاق أو افترض قاعدة:**
```text
توقف. ما المرجع لهذا (ملف وسطر)؟ إن لم يكن في المواصفات أو decisions.md فتراجع عنه، وأضف بنداً مفتوحاً D-xx بالسؤال، ثم انتظرني.
```

**فشل اختبار لا علاقة له بالحزمة:**
```text
لا تصلحه داخل هذه الحزمة. سجّله في notes.md، واقترح حزمة إصلاح عاجل HF في docs/03-plan/hotfixes.md، ثم أكمل الحزمة الحالية إن لم يكن حاجباً.
```

**تريد رأي وكيل بعينه:**
```text
شغّل وكيل ledger-auditor على الفرع الحالي وأعطني الملاحظات الحاجبة فقط.
```

## القرارات وطلبات التغيير

**تجهيز قرار:**
```text
جهّز ملخص قرار لـ D-<رقم>: البدائل، أثر كل بديل على البيانات والجدول الزمني، توصيتك وسببها. لا تعدّل decisions.md.
```

**تسجيل قرار اتخذته:**
```text
اعتمدت D-<رقم> بالخيار: <الخيار>. حدّث الحالة إلى Approved في decisions.md مع التاريخ، وانقل الأثر إلى ADR أو CR إن لزم، واذكر الحزم المتأثرة.
```
تنبيه: هذا من الحالات القليلة التي يغيّر فيها Claude حالة قرار، لأنك طلبت ذلك صراحة.

**طلب تغيير على المواصفات:**
```text
اكتب مسودة CR-<رقم> لـ <التغيير> بقالب change-control.md: النص قبل وبعد، والأثر على البيانات والخطة والاختبارات. لا تعدّل ملفات المواصفات.
```
