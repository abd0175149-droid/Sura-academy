## واجهات API والـ webhooks والمهام الخلفية

واجهة REST بصيغة JSON موثقة بمواصفة OpenAPI 3.1 تُولّد منها الوثائق والاختبارات. كل ما يغير المال أو الرصيد يقبل مفتاح منع التكرار، وكل حدث خارجي يُعالج مرة واحدة فقط.

### اصطلاحات الواجهة

| البند | المواصفة |
| --- | --- |
| الإصدار | المسار `/api/v1`، ولا كسر للتوافق داخل الإصدار |
| المصادقة | جلسات بملفات ارتباط HttpOnly وSecure وSameSite=Lax لتطبيقات الويب، مع رمز CSRF؛ رمز قصير العمر لوضع الطفل |
| منع التكرار | ترويسة `Idempotency-Key` إلزامية لإنشاء الدفع والاشتراك والاسترداد والقيود اليدوية |
| الأخطاء | كائن موحد: `code` ثابت للبرمجة، ورسالة عربية وإنجليزية، وتفاصيل الحقول |
| الصفحات | ترقيم بالمؤشر (cursor) مع مرشحات وترتيب محددة لكل مورد |
| حدود الاستخدام | لكل عنوان IP ولكل مستخدم، وأشد على الدخول ورموز التحقق والنماذج العامة |
| التتبع | معرّف طلب في كل استجابة وسجل، يظهر للمستخدم في رسائل الخطأ لتسهيل الدعم |
| الوقت | كل الأوقات في الاستجابات بصيغة ISO 8601 بتوقيت UTC، والواجهة تحولها لمنطقة المستخدم |

### الأحداث الواردة (webhooks)

نقاط مثل `/webhooks/payments/{provider}` و`/webhooks/video/{provider}` تتحقق من التوقيع، وتحفظ الحدث خاماً في `webhook_events`، وترد خلال ثانية، ثم تعالجه مهمة خلفية. الحدث المكرر أو المتأخر أو الوارد بغير ترتيبه لا يغير النتيجة، والفاشل يُعاد بتأخير متزايد ثم يدخل قائمة مراجعة.

داخلياً، كل وحدة تنشر أحداث نطاق مثل `SessionEnded` و`AttendanceConfirmed` و`PaymentSucceeded` عبر جدول صادر (outbox) في المعاملة نفسها، فلا يضيع حدث إذا تعطلت الطوابير.

### المهام الخلفية المجدولة

| المهمة | التكرار | ما تفعله |
| --- | --- | --- |
| توليد الجلسات | يومياً | تمد جلسات كل شعبة نشطة إلى ثمانية أسابيع قادمة |
| فحص التوقيت الصيفي | يومياً | يكشف الجلسات المتأثرة خلال 21 يوماً وينشئ الإشعارات |
| تذكير الحصص | كل 5 دقائق | قبل 24 ساعة وقبل ساعة، حسب تفضيلات كل أسرة |
| معالجة نهاية الحصة | عند الحدث | تقترح الحضور من سجل الدخول والخروج وتنشئ مهمة التأكيد |
| اعتماد الحضور المتأخر | كل ساعة | تعتمد المقترح بعد 12 ساعة وتعلّمه للمشرف |
| التجديد | كل ساعة | تخصم من البطاقة المحفوظة عند بلوغ حد الرصيد |
| تحصيل الفاشل | يومياً | إعادة المحاولة في الأيام 1 و3 و5، ثم الإيقاف بعد المهلة |
| انتهاء صلاحية الرصيد | يومياً | تكتب قيود الانتهاء وتنبه الأسرة قبلها بأسبوع |
| مهام التقارير | أسبوعياً وشهرياً | تنشئ المهام وتنبه عند التأخر |
| حذف التسجيلات المنتهية | يومياً | تحذف من التخزين وتسجل الحذف |
| الاحتفاظ بالبيانات | أسبوعياً | تطبق جدول الاحتفاظ على الملفات والعملاء المحتملين والسجلات |
| مستحقات المعلمات | أول كل شهر | تحسب الكشوف وترسلها للمالية للاعتماد |
| مطابقة قائمة الانتظار | يومياً | تنبه العمليات عند توافق 3 طلاب |
| التسوية المالية | يومياً | تستورد تقارير البوابة وتطابقها (R2) |
