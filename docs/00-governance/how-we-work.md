# كيف نعمل: صاحب المشروع وClaude Code

## الأدوار

| الدور | المسؤولية |
| --- | --- |
| صاحب المشروع | يعتمد الدستور والقرارات وطلبات التغيير، يوافق على تصميم كل حزمة قبل الكود، يجري التجارب على الأجهزة، يتعامل مع المزودين والمستشارين، يقرر عند البوابات |
| Claude Code | ينفذ حزم العمل بالترتيب، يكتب التصميم والاختبارات والكود، يشغّل البوابات، يحدّث الحالة، يتوقف ويسأل عند أي غموض |
| وكلاء المراجعة | يراجعون كل حزمة في مجالهم (الدفتر، الخصوصية، الاتجاه، الأمن، التتبع) ويرفعون ملاحظات حاجبة |
| المستشار القانوني والضريبي | يحسم D-13 وD-15 وD-17 قبل مواعيدها |

## دورة حزمة العمل

1. **اختيار:** `/sura-status` يعرض الحزمة التالية حسب ترتيب التنفيذ في `master-plan.md`.
2. **التحضير:** `/sura-wp WP-x.y` يقرأ قسم الحزمة والملفات المحددة فقط، ويتحقق من الاعتماديات والقرارات.
3. **التصميم:** يكتب `specs/WP-x.y/design.md` و`tasks.md` ثم يتوقف. أنت تراجع وتوافق أو تطلب تعديلاً.
4. **التنفيذ:** مهمة مهمة: اختبار ثم كود ثم تحقق ثم commit.
5. **التحقق:** `/verify` كاملاً ثم وكلاء المراجعة.
6. **الإغلاق:** تحديث الحالة والتتبع وملاحظات العرض، وفتح PR.
7. **أنت:** تراجع الـ PR وخطوات العرض في `notes.md`، ثم تدمج.

## إيقاع العمل المقترح

- جلسة واحدة لكل حزمة عمل، و`/clear` بين الحزم.
- الحزم الكبيرة (المحركات) قد تحتاج عدة جلسات: كل جلسة تبدأ بـ `/sura-wp WP-x.y` فيكمل من آخر مهمة غير منجزة في `tasks.md`.
- مراجعة أسبوعية: `/sura-status` + سجل القرارات المفتوحة + المخاطر.

## متى يتوقف Claude ويسألك

- قرار بحالة Open تحتاجه الحزمة.
- تعارض بين المواصفات والقرارات أو بين ملفين.
- حاجة لتثبيت حزمة برمجية غير مذكورة في ADR (يطلب الإذن).
- فشل اختبار لا يتعلق بالحزمة الحالية.
- أي عمل يمس حساباً حقيقياً أو مالاً حقيقياً أو بيانات حقيقية.

## ما لا يفعله Claude أبداً

يعدّل المواصفات أو الدستور، يكتب أسراراً، يعطّل اختباراً، يدفع إلى main، يبني خارج نطاق الحزمة، يخترع قاعدة عمل.
