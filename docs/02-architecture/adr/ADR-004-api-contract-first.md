# ADR-004: عقد OpenAPI أولاً وعميل Dart مولَّد

- الحالة: Accepted · التاريخ: 2026-10-08

## القرار
1. `contracts/openapi/sura-api.v1.yaml` (OpenAPI 3.1) هو مصدر الحقيقة، مقسم بمراجع `$ref` إلى ملفات لكل وحدة في `contracts/openapi/modules/`.
2. ترتيب العمل لكل نقطة نهاية: العقد ← اختبار عقد فاشل ← التنفيذ ← نجاح الاختبار ← توليد العميل.
3. **التحقق في Laravel:** اختبارات الميزات تمرر كل استجابة عبر مدقق العقد (league/openapi-psr7-validator داخل مساعد اختبار واحد).
4. **التوليد في Dart:** حزمة `swagger_parser` (Dart خالصة، دون Java) تولد النماذج والعميل داخل `packages/sura_api/lib/src/generated/`. السكربت `scripts/gen-api-client.sh`. لا تعديل يدوي؛ التخصيص في طبقة مستودعات داخل التطبيقات.
5. **فحص العقد:** Redocly CLI في خط التكامل المستمر.

## الاصطلاحات
مذكورة في مهارة `api-contract` وملخصها: المسار `/api/v1`، كائن الخطأ الموحد، الترقيم بالمؤشر، `Idempotency-Key`، أوقات UTC، `Accept-Language` للرسائل.

## البدائل المرفوضة
توليد العقد من الكود (code-first): يجعل العقد تابعاً للتنفيذ ويضعف الاتفاق المسبق مع واجهات Flutter.
