# ضبط التغيير (Change Control)

المواصفات في `docs/01-product/spec/` مجمدة. أي تعديل عليها، أو إضافة ميزة، أو تغيير رقم غير وظيفي، يمر بطلب تغيير.

## متى تحتاج CR؟
- إضافة متطلب جديد أو تغيير نطاق متطلب قائم.
- نقل متطلب بين R1 وR2 وR3.
- تغيير قاعدة عمل أو نوع قيد في الدفتر أو حالة في دورة حياة كيان.
- تغيير رقم في المتطلبات غير الوظيفية.
- استبدال تقنية مذكورة في المواصفات.

القرارات التي تفسر غموضاً دون تغيير النص تكفيها `decisions.md`.

## الإجراء
1. انسخ القالب أدناه إلى `change-requests/CR-xxx.md` برقم تالٍ.
2. املأ الأثر على البيانات والخطة والاختبارات.
3. صاحب المشروع يعتمد أو يرفض ويوقّع بالتاريخ.
4. عند الاعتماد: يُحدَّث ملف المواصفات المعني (بيد صاحب المشروع أو بتكليف صريح لـ Claude داخل CR)، ويُحدَّث `traceability.md` والحزم المتأثرة.
5. لا يبدأ تنفيذ أي شيء في CR قبل حالته Approved.

## القالب

```markdown
# CR-xxx: العنوان
- الحالة: Proposed | Approved | Rejected
- التاريخ / المقترح / المعتمد:
- المتطلبات المتأثرة:
## السبب
## التغيير المقترح (النص قبل وبعد)
## الأثر: البيانات / الواجهة / الخطة والجدول الزمني / الاختبارات / الامتثال
## البدائل المرفوضة
```
