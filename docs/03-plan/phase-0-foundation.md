# المرحلة 0: التأسيس والقرارات (الأسابيع 0–6، البوابة ب0)

**الهدف:** مستودع جاهز بأدواته وضوابطه، ثلاث تجارب تقنية تحسم أعلى المخاطر (الفيديو، Flutter على الويب، الدفع)، ونموذج بيانات معتمد، وقرارات محسومة قبل كتابة أي منطق عمل.

قالب كل حزمة: الجدول يحدد النافذة والاعتماديات والقرارات والمتطلبات وما يُقرأ والمراجعات؛ ثم الهدف والمخرجات والاختبارات ومعايير القبول وما هو خارج النطاق.

**الهدف:** مستودع أحادي يعمل محلياً وفي CI، بهيكل `architecture.md` حرفياً.

**المخرجات:**
1. ملفات الجذر: `.editorconfig`، `.gitattributes` (LF)، `README.md` يشير إلى `START_HERE.md`. فرع `main` محمي في GitHub (يضبطه صاحب المشروع).
2. `apps/api`: مشروع Laravel 13 جديد (`composer create-project laravel/laravel apps/api`):
   - PostgreSQL وRedis، `SESSION_DRIVER=redis`، حذف هجرة جدول `sessions` الافتراضية، `APP_TIMEZONE=UTC`، اللغة `ar` والبديلة `en`.
   - هيكل `app/Modules/<Module>/` للوحدات الإحدى عشرة: Identity, Families, Curriculum, Scheduling, Live, Ledger, Billing, Learning, Messaging, Teachers, Platform، داخل كل منها `Actions/ Contracts/ Events/ Http/ Jobs/ Models/ Policies/ Filament/`.
   - `ModulesServiceProvider` يسجل مسارات كل وحدة وسياساتها تلقائياً.
   - Pest مع إضافة arch، وLarastan بالمستوى 8، وPint بإعداد المشروع.
   - `tests/Arch/ModulesTest.php`: يمنع وحدة من استيراد `Models` وحدة أخرى.
3. تثبيت الحزم المذكورة في ADR-002 فقط، وملء جدول «الإصدارات المثبتة» فيه.
4. Laravel Boost: `composer require laravel/boost --dev` ثم `php artisan boost:install` (اختيار Claude Code). يُبقى `apps/api/CLAUDE.md` الذي يولده (يُحمَّل عند العمل داخل `apps/api`). لا يُستبدل `.mcp.json` في الجذر.
5. مساحة Dart:
   - `pubspec.yaml` في الجذر بقائمة `workspace:` للتطبيقات والحزم.
   - `flutter create` لـ `apps/family` (web, ios, android) و`apps/teacher` (web).
   - الحزم الست في `packages/` بـ `resolution: workspace`.
   - `analysis_options.yaml` مشترك يرث `very_good_analysis`.
   - ARB عربي وإنجليزي في كل تطبيق.
6. `infra/docker/compose.yaml`: postgres:17، redis:7، mailpit، minio، gotenberg، clamav، مع فحوص صحة. `apps/api/.env.example` مطابق.
7. `.github/workflows/ci.yml`: وظائف api وdart وcontract وtraceability، تستدعي `scripts/verify.sh --all`، مع تخزين مؤقت.

**الاختبارات:** اختبار المعمارية؛ اختبار Pest مثال؛ اختبار widget مثال لكل تطبيق.

**معايير القبول:**
- [ ] `docker compose -f infra/docker/compose.yaml up -d` وكل الخدمات بحالة healthy.
- [ ] `php artisan migrate` يعمل على PostgreSQL المحلي، ولا جدول `sessions`.
- [ ] `flutter build web --wasm --no-web-resources-cdn` ينجح لـ family وteacher.
- [ ] `bash scripts/verify.sh --all` أخضر، وCI أخضر على أول PR.
- [ ] جدول الإصدارات في ADR-002 مملوء.

**خارج النطاق:** أي جدول نطاق، مصادقة، أو واجهة.

### WP-0.4 تجربة تقنية: مزود الفيديو

| البند | القيمة |
| --- | --- |
| النافذة | الأسابيع 1–3 |
| يعتمد على | WP-0.1 |
| القرارات | D-20 (تحسمه هذه الحزمة) |
| المتطلبات (جدوى فقط) | CLS-01..05، CLS-09، CLS-10، CLS-13، CLS-14 · الدخول < 10 ث (NFR) |
| اقرأ فقط | ADR-005 · `spec/05-live-classroom.md` · `spec/16-external-services.md` · `spec/18-non-functional-requirements.md` |
| المراجعات | privacy-reviewer |
| مهام صاحب المشروع | حسابات LiveKit Cloud وZoom Video SDK؛ الأجهزة؛ جلسات اختبار بأربعة مشاركين |

**الهدف:** قرار مبني على أرقام بين LiveKit وZoom لتطبيق Flutter على الويب وiOS وAndroid.

**المخرجات (كود تجريبي في `spikes/video/`، لا يُدمج في `apps/`):**
1. نقطة PHP صغيرة تصدر رموز دخول لكل مزود بأدوار (معلمة، طالب، مشرف).
2. تطبيق Flutter تجريبي يدخل غرفة بأربعة مشاركين:
   - LiveKit: الويب وAndroid وiOS.
   - Zoom: Android وiOS عبر `flutter_zoom_videosdk`، مع تقدير جهد تكامل الويب عبر JavaScript.
3. التقاط webhooks الدخول والخروج، وتشغيل تسجيل سحابي وتنزيله.
4. جدول قياس: زمن الدخول حتى ظهور الفيديو (20 محاولة لكل جهاز)، السلوك عند 1.5 ميغابت والتحول للصوت، الكتم وإخراج المشارك، منطقة البيانات.
5. حساب التكلفة الشهرية: 100 حصة متزامنة × 4 مشاركين × مدة متوسطة 75 دقيقة × 8 حصص لكل طالب شهرياً.

**معايير القبول:**
- [ ] ADR-005 مكتمل بقسم «القرار» والأرقام، وD-20 بحالة Closed.
- [ ] كل معيار في جدول ADR-005 له نتيجة مقاسة.

**خارج النطاق:** كود إنتاجي.
