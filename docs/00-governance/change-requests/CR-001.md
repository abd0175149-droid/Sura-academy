# CR-001: Flutter لتطبيقات الأسرة والمعلمة، ومرشح مزود الفيديو

- الحالة: Proposed (يُعتمد بتوقيع صاحب المشروع؛ القرار التقني في ADR-003 وADR-005)
- التاريخ: 2026-10-08 · المقترح: صاحب المشروع (قرار المنصة متعددة الأجهزة)
- الأقسام المتأثرة: `13-architecture-original.md` · `16-external-services.md` · `18-non-functional-requirements.md` (انظر CR-003)

## السبب
صاحب المشروع يريد منصة تعمل على الويب والأجهزة المختلفة من قاعدة كود واحدة. Flutter يغطي تطبيق الأسرة (ولي الأمر ووضع الطفل) وبوابة المعلمة على الويب الآن، وعلى iOS وAndroid لاحقاً، ويناسب تجربة الطفل التفاعلية (الكتابة بالإصبع، لوحة المفاتيح، الألعاب) بعرض متطابق على الأجهزة.

## التغيير المقترح في جدول البنية التقنية
| الطبقة | قبل | بعد |
| --- | --- | --- |
| واجهات الأسرة والمعلمة | Vue 3 عبر Inertia | Flutter (ويب أولاً كتطبيق قابل للتثبيت، ثم iOS وAndroid من الكود نفسه) |
| التنسيق | Tailwind CSS بخصائص منطقية | Tailwind CSS بخصائص منطقية للموقع العام ولوحة الإدارة فقط؛ تطبيقات Flutter بالواجهات الاتجاهية |
| الموقع العام | ضمن الواجهات | Laravel Blade + Tailwind (توصية Flutter نفسه: المحتوى النصي الثابت والمحسّن للبحث يُبنى بـ HTML) |
| لوحة الإدارة | Filament | بلا تغيير |
| الفصل الافتراضي | المرشح الأول Zoom Video SDK | المرشحان LiveKit وZoom؛ يُحسم بتجربة WP-0.4. حزمة Zoom لـ Flutter تغطي iOS وAndroid فقط، وحزمة LiveKit لـ Flutter تغطي الويب وiOS وAndroid وسطح المكتب |
| التطبيق القابل للتثبيت | PWA مع Service Worker | بلا تغيير في R1 (Flutter web كـ PWA مع Service Worker مخصص)؛ التطبيقات الأصلية تبقى R3 أو حسب D-19 |

## الأثر
- **البيانات:** لا أثر.
- **الخطة:** WP-1.6 (نظام التصميم في Flutter)، WP-3.4 (واجهة الفصل)، WP-4.2 إلى WP-4.6 تُبنى بـ Flutter. WP-0.5 تجربة تقنية لأداء Flutter على الويب في Safari على iPad.
- **الاختبار:** لقطات golden في Flutter، واختبارات Playwright للويب بعد تفعيل شجرة إمكانية الوصول.
- **الامتثال:** لا موارد من خوادم Google في واجهة الطفل (بناء دون CDN وخطوط مضمّنة).

## البدائل المرفوضة
- Flutter لكل شيء بما فيه الموقع العام ولوحة الإدارة: يضعف تحسين البحث ويثقل لوحة الإدارة بالجداول.
